# Pinecrest RolePlay — документация проекта

Игровой **ролевой сервер для SA-MP 0.3** (San Andreas: Multiplayer), тематика
Vice City, русскоязычный. Серверная логика написана на **Pawn**, данные
хранятся в **MySQL**.

## Обзор

| Параметр | Значение |
|----------|----------|
| Платформа | SA-MP 0.3 (Linux, 32-bit) |
| Язык логики | Pawn (community compiler 3.10.x) |
| База данных | MySQL (кодировка `cp1251`) |
| Кодировка исходников | Windows-1251 |
| Главный геймод | `gamemodes/main.pwn` (~72 000 строк) |
| Модулей (`.inc`) | ~200 файлов в `gamemodes/logic/` |

> ⚠️ Исходники в кодировке **Windows-1251**. В UTF-8 редакторе русские
> комментарии выглядят как «кракозябры» — это нормально. Новые файлы желательно
> писать ASCII-комментариями, чтобы не зависеть от кодировки.

## Архитектура геймода

Весь геймод собирается из одного файла `gamemodes/main.pwn`, который через
`#include` подключает:

1. **Библиотеки** (`pawno/include`): `a_samp`, `a_mysql`, `streamer`, `sscanf2`,
   `pawncmd`, `Pawn_RakNet`, `YSI`/`foreach`, `bcrypt`, `TOTP`, `voicechat` и др.
2. **`logic/core.inc`** — главный «сборщик»: содержит ~180 директив `#include`,
   подключающих все игровые модули в нужном порядке (сначала `*_var.inc` с
   переменными/енумами, затем файлы с логикой).

Включения внутри `logic/` записаны относительно папки `gamemodes/`
(например `#include "logic/inventory/inventory.inc"`), поэтому компилятор
запускается из корня репозитория с `-igamemodes` (см. [Сборка](#сборка)).

**Точки входа** (стандартные коллбэки SA-MP) находятся в `main.pwn`:
`OnGameModeInit`, `OnPlayerConnect`, `OnPlayerCommandText`, `OnPlayerUpdate`,
`OnDialogResponse` и т.д. Команды чата реализованы через плагин **pawncmd**
(`pawncmd`), диалоги — через `fdialog`.

## Конфигурация

Настройки разделены на два уровня:

### 1. `server.cfg` — настройки самого сервера SA-MP
Читается бинарником `samp03svr` ещё до запуска геймода. Здесь задаются:
`port`, `maxplayers`, `hostname`, `plugins`, `gamemode0`, `rcon_password`,
rate-настройки синхронизации, `stream_distance` и т.д.

### 2. `scriptfiles/.env` — настройки геймода (рантайм)
Читается геймодом при старте (`gamemodes/logic/server_config.inc`).
Позволяет менять БД / имя / id сервера **без перекомпиляции**. Формат `KEY=VALUE`.

| Переменная | Назначение | По умолчанию |
|------------|-----------|--------------|
| `MYSQL_HOST` | адрес MySQL | `127.0.0.1` |
| `MYSQL_USER` | пользователь БД | `pinecrestphp` |
| `MYSQL_PASSWORD` | пароль БД | *(встроенный)* |
| `MYSQL_DATABASE` | имя базы | `pinecrestphp` |
| `SERVER_NAME` | имя в браузере / gamemode text | `Pinecrest RolePlay` |
| `SERVER_ID` | логический id инстанса (`-1` = авто по порту) | `-1` |

Если `.env` отсутствует — используются встроенные значения по умолчанию
(старое поведение, сервер всё равно стартует). Шаблон: `scriptfiles/.env.example`.

> Игровой `port` остаётся в `server.cfg` (его читает бинарник до запуска
> геймода). `SERVER_ID` в `.env` даёт стабильный id инстанса независимо от порта.

## Сборка

Скрипт `compile.sh` собирает геймод под Linux **без Windows-pawno**. При первом
запуске он скачивает компилятор `pawn-lang` (v3.10.4) в `.compiler/` и собирает
геймод теми же флагами, что и CI (`-ipawno/include -igamemodes -;+`).

```bash
./compile.sh              # собрать gamemodes/main.pwn -> gamemodes/main.amx
./compile.sh cameditor    # собрать gamemodes/cameditor.pwn
./compile.sh gamemodes/x  # явный путь к .pwn
```

**Требования:** `bash`, `curl` (или `wget`), `tar` и 32-битная glibc.
Компилятор — 32-битный (i386), как и сам `samp03svr`, поэтому на любом хосте,
где работает сервер, он запустится. На «чистой» Debian/Ubuntu:

```bash
sudo dpkg --add-architecture i386
sudo apt-get update
sudo apt-get install -y libc6:i386
```

> Компиляция большая (~72k строк) и занимает несколько минут на старом
> компиляторе — это нормально, процесс не завис.

Результат — `gamemodes/main.amx`, который и запускает сервер.

## Запуск сервера

```bash
./samp03svr            # запуск в текущем терминале
./samp03svr &          # запуск в фоне
```

Сервер читает `server.cfg`, грузит плагины и геймод `main` (`main.amx`).
Healthcheck: геймод периодически пишет timestamp в `scriptfiles/healthz.txt`.

## База данных

- MySQL, кодировка соединения `cp1251` (`mysql_set_charset("cp1251")`).
- Подключение — в `OnGameModeInit` (`mysql_connect(...)`), параметры берутся
  из `.env` (см. [Конфигурация](#конфигурация)).
- Основные таблицы: `accounts`, `house`, `biz`, `family`, `box_coords`,
  `edit_advertise`, `bizz_finka` и др. Данные подгружаются на старте
  (`load_house`, `load_bizz`, `LoadDatabaseInfo`).

## CI/CD

`.gitlab-ci.yml` собирает геймод в образе `southclaws/sampctl` командой:

```bash
pawncc gamemodes/main.pwn -o"gamemodes/main.amx" -i"pawno/include" -i"gamemodes" "-;+"
```

`compile.sh` повторяет эти флаги, поэтому локальная и CI-сборка идентичны.
После сборки артефакт — весь репозиторий; затем job `notify-bot-job`
дёргает вебхук деплоя.

## Многосерверный режим

Один и тот же `main.amx` можно запускать на нескольких серверах. Для каждого
инстанса:

1. Скопировать `scriptfiles/.env.example` → `scriptfiles/.env` и заполнить
   свои `MYSQL_*`, `SERVER_NAME`, `SERVER_ID`.
2. В `server.cfg` указать свой `port`.

`SERVER_ID` доступен в коде как `SRV_ID` и используется для пер-серверной логики
(разные правила, транспорт, доступы и т.п.). При `SERVER_ID=-1` id определяется
автоматически по порту (legacy-режим).
